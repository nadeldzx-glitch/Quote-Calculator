## v163 - 修复重置按钮无法真正重置的问题
- **问题**：点击"重置"按钮只恢复到上一次保存的模板（或本次输入后的快照），无法回到 HTML 原始默认值。刷新页面可以正常重置。
- **根因**：`resetAll()` 只调用 `applyDefaults()`，而 `defaults` 对象在页面运行期间已被 `captureDefaults()` 从 `localStorage` 加载过，导致 defaults 里存的是用户修改后的值，而非 HTML 初始值。
- **修复**：`resetAll()` 现在会：
  1. 清空 `localStorage` 中的 `bh_quote_template` 和 `bh_material_prices`
  2. 清空内存中的 `defaults` 对象
  3. 重新调用 `captureDefaults()` 从 HTML 初始值重新抓取
  4. 再执行 `applyDefaults()` 恢复 UI
- **版本**：v162 → v163

## v164 - 真正修复重置无效（v163 的修复本身有 bug）
- **症状**：点重置值不变，刷新页面才重置。
- **根因**：v163 的 `resetAll()` 清 localStorage 后调 `captureDefaults()`，其 else 分支 `defaults[el.id]=el.value` 是从**当前 DOM**（用户输入值）抓取，再 applyDefaults 写回 = 没变化；刷新时 DOM 是全新的才抓到真初始值。另外内存 `materialPrices` 未清，价格字段也重置不掉。
- **修复**：新增 `const htmlDefaults = {}`，`captureDefaults()` 首次调用时（页面加载、用户未输入前）快照 HTML 出厂值；`resetAll()` 改为 `Object.assign(defaults, htmlDefaults)` 直接从快照恢复（不再调 captureDefaults），并清空内存 `materialPrices` 和 `state.lastBoxStyle`。同时清理了行 713-715 残留的两个多余 `</div>`。
- **教训**：重置功能绝不能从"当前 DOM"反抓默认值——DOM 已被用户改过。必须在页面加载时先快照出厂值。
- **版本**：v163 → v164
- **部署链接**：https://f2dace729d844584ae23ed7275c41088.sh5.agentos-app.net
