## v164 完成：修复"存为模板失效"（不破坏重置功能）

**问题根因（两个叠加）**：
1. v163/v164 的 `resetAll()` 里 `localStorage.removeItem('bh_quote_template'/'bh_material_prices')` —— 存好模板后点一次重置，模板被永久删除。
2. 模板版本校验是严格相等 `saved._v === TEMPLATE_VERSION`，每次纯逻辑修改 bump 版本号导致用户已存的旧模板被误判失效（v163 存的模板到 v164 就被拒）。

**修复内容（index.html，3+2 处编辑）**：
- 新增 `TEMPLATE_MIN_VERSION = 163`，校验改为区间 `saved._v >= MIN && <= TEMPLATE_VERSION`；并加注释警告：只有 DOM/字段结构变化才允许 bump 版本号，纯 JS 逻辑修复不要 bump。
- `resetAll()` 不再碰 localStorage；改为清空内存 defaults/materialPrices → `captureDefaults()` 完全模拟全新页面加载（有模板→恢复模板；无模板→恢复出厂快照 htmlDefaults）→ `applyDefaults()`。两条路径都不从当前 DOM 反抓，重置立即生效的老修复（v164 出厂快照机制）不受影响。
- 新增 `hasSavedTemplate()` 辅助函数；重置确认弹窗文案动态化（`<p id="resetConfirmText">`）：有模板显示"恢复为已保存的模板"，无模板显示"恢复为出厂默认值"；toast 同步区分。
- `captureDefaults()` else 分支改为从 `htmlDefaults` 快照取值（此前中断前已完成）。

**验证**：JS 语法校验通过；全文已无 `removeItem`。
**部署**：https://f2dace729d844584ae23ed7275c41088.sh5.agentos-app.net （sandbox f2dace729d844584ae23ed7275c41088）

**重要教训（重置 vs 模板设计原则）**：
- 重置 = 模拟刷新页面，不是清空存储。localStorage 里的用户模板是"数据资产"，任何重置逻辑都不得删除。
- 模板版本号 bump 只对应 DOM 结构变化；纯逻辑修复用 `TEMPLATE_MIN_VERSION` 区间兼容旧模板。
